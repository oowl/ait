# Android 与桌面工作区加载恢复

## 问题与修复

主界面已经出现后，工作区可能持续加载。这次修复三条共享路径，适用于 Android、桌面及使用同一客户端的其他平台。

1. **前台检查误断开健康连接。** 客户端此前使用带服务端时间戳的 session ping，但 Rust transport 明确拒绝该能力。检查改为适配器支持的 transport 心跳，并保留独立的三秒截止时间，避免复用后台尚未结束的心跳时等待过久。旧连接的检查不能关闭替换后的连接。
2. **工作区依赖侧栏或聊天标签页触发同步。** 当前聚焦的工作区现在持有自己的目录需求，即使没有缓存、侧栏关闭且没有打开聊天，也会加载数据。离开、切换工作区或卸载时释放需求；仍有其他消费者时保留共享订阅。
3. **首次同步失败后无限 loading。** 目录需求刷新失败后按 1、2、4……秒退避重试，间隔上限为 30 秒；成功后重置。取消需求、断线或销毁时清理计时器。手动重试跳过退避，并取消旧计时器，避免重复请求。

工作区同步错误通过 runtime snapshot 传给路由，显示“无法加载工作区”、错误原因和重试按钮。已有缓存内容继续显示；自动重试期间保留错误，成功后清除。过期连接的失败不会覆盖新连接的结果。快速离开并返回页面时，会重新建立已释放的订阅。

此次没有更改服务端、协议或领域边界，也没有缩短普通 RPC 的默认超时。无响应的请求仍可能等到现有超时后才进入失败恢复。

## 验证

定向 Vitest 验证通过：

- `packages/client/src/daemon-client.test.ts` 中四个前台检查用例：健康连接、无响应连接、后台已有心跳、旧检查与新连接竞态。
- `apps/app/src/runtime/rust-server/transport.test.ts`：真实客户端与 Rust 适配器组合，验证前台检查保留健康连接。
- `apps/app/src/runtime/directory-sync/index.test.ts`：失败退避、成功清除错误、手动重试、需求释放/断线/销毁取消重试、旧失败隔离及重新订阅。
- `apps/app/src/runtime/host-runtime.test.ts`：现有主机 runtime 行为。
- 工作区目录需求 hook、路由状态、错误页重试按钮及 source-of-truth 测试。
- i18n 资源与诊断报告测试。

测试使用临时 Vitest 配置将本地 SDK 和协议直接指向当前工作树源码，避免复用环境中的旧构建产物。网络故障和等待时间由假 socket、假响应及模拟时钟控制，不代表整机启动耗时测量。

格式检查、Oxlint 和 `git diff --check` 通过。SDK 在使用当前协议源码的 TypeScript 配置下通过检查。

完整 App 类型检查受环境缺失的 `expo-clipboard`、键盘控制器、终端组件等依赖及现有声明问题阻塞。Expo ESLint 同样在原有 `expo-clipboard` 导入处报无法解析，并有原有风格警告；本次没有改动这些导入或扩大修复范围。

提交前执行了完整 App 单元测试及 SDK 测试（排除 browser 项目）：593 个测试文件中，573 通过、19 失败、1 跳过；5292 个用例中，5281 通过、10 失败、1 跳过，另有两个运行环境错误。本次新增/修改的六个回归测试文件共 203 个用例全部通过。

完整测试未通过的原因包括缺失键盘控制器、`htmlparser2`、`expo-clipboard`、`@xterm/headless`，沙箱禁止子进程或监听端口，以及未改动的插件行身份/去重和 daemon 错误文案断言。没有将这些结果计为通过，也没有扩大修复范围。
